Audit date: 2026-11-24

Scope: tracked repository tree on `main`, including frontend entry points, browser JavaScript, NestJS API controllers, role guard, build configuration and existing automated checks.

## Confirmed defect

| Severity | File | Finding | Impact | Resolution |
|---|---|---|---|---|
| Critical (P1) | `src/auth/auth.ts` — `RolesGuard.canActivate` | The guard read role metadata only from `ctx.getHandler()`. NestJS controller-level `@Roles('super_admin')` metadata was ignored on methods without their own `@Roles` decorator. | Authenticated non-admin accounts could pass the guard on class-protected Platform Admin and Platform Finance methods that had no method-level role metadata. | Resolve metadata from both handler and controller with `Reflector.getAllAndOverride`. Method-level metadata continues to override controller-level metadata. |

Affected class-protected controllers:
- `src/platform-admin/platform-admin.controller.ts`
- `src/platform-admin/platform-operations.controller.ts`
- `src/platform-admin/ai-maintenance.controller.ts`
- `src/platform-admin/ai-repair.controller.ts`
- `src/platform-finance/platform-finance.controller.ts`

## Regression coverage added

- `test/roles-guard.test.mjs` exercises the real RolesGuard with Nest's Reflector.
- Confirms controller-level super-admin restrictions apply to methods without method metadata.
- Confirms method-level roles override controller-level roles.
- Confirms vendor, freelancer, cashier and customer identities cannot pass a super-admin-only controller guard.
- CI now runs this regression test.
